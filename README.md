# Bharosa Check

**An explainable, private, on-device scam check for Indian retail investors.** Paste or share a suspicious tip, link, screenshot or whole group chat and get a red / amber / green verdict in **English or Hindi**, with every warning sign highlighted, explained in plain language, and read aloud on request. It never gives tips, never sells anything, and never says "safe".

**Live demo:** `https://<your-username>.github.io/bharosa-check/` (deployed automatically by GitHub Actions, see [Deploy](#deploy))

Built for **Track A: Digital Fraud and Scam Resilience** (Scam and Claim Verifier + Tip-Group Risk Profiler).

## The problem and the user
India has 16 crore+ Demat accounts and most new ones come from Tier-2/3 cities, yet 9 in 10 individual F&O traders lose money (SEBI). Fake SEBI numbers, cloned broker sites, Telegram/WhatsApp pump-and-dump groups and remote-access apps catch people before they ever place a trade.

**Who it is for:** a retired, Hindi-comfortable first-time investor in a Tier-2/3 town who has just been added to a "VIP tips" group and is being pushed to install an app and pay a fee.

## What it does
| Feature | How |
|---|---|
| Scam and Claim Verifier | 13 pattern rules plus 7 structural checks (look-alike broker domains, SEBI registration-number format, unusual website endings, shortened links, group-level signals). Personal UPI payees are flagged and `@valid` handles are noted |
| Tip-Group Risk Profiler | Paste a chat export: each message is analysed, then group signals are added (tip-style share, one "admin" driving the calls, fake profit proof) |
| Screenshot input | On-device OCR (Tesseract.js, lazy-loaded, English + Hindi). The image never leaves the phone |
| Regional language | Full English and Hindi interface, results, voice read-aloud, and detection of Hindi and Hinglish scam phrases. Add a language by copying one file |
| Real SEBI mechanisms | Points users to **SEBI Check** and **@valid UPI handles** (e.g. `name.brk@validbank`) to verify a payee before paying |
| Recovery path | "I already paid" guide: 1930, bank, cybercrime.gov.in, no recovery-fee traps |
| Low-bandwidth and low-end ready | No framework, no backend, under 50 KB of code in total (about 16 KB of logic, the rest is English and Hindi text and styling), offline after first visit (service worker), installable PWA |
| One-tap share | As an installed PWA it appears in the phone's Share menu (Web Share Target), so a WhatsApp message can be sent straight in |
| Accessibility | Voice read-aloud, large-text button, high-contrast colours, three-colour verdict |

## How a verdict is made
```
 text / OCR / chat  ->  rule engine  ->  score  ->  verdict + reasons
                        13 patterns     100 x (1 - product of (1 - weight))
                        + domain, SEBI-number, UPI, group checks
```
Each warning sign has a visible weight. Signs combine so that several weak signals add up but the score never exceeds 100. **A high score is not proof of fraud and a low score is not proof of safety**: levels are High (55+), Be careful (20-54) and No major red flags found (below 20), and the last one always says it is not a guarantee. A negation guard stops genuine education such as "no scheme can guarantee returns" from being flagged.

## Guardrails (from the problem statement)
- **No commercial outcome:** no stock tips, buy/sell/hold signals, price predictions, or product/broker promotion. It uses no market data at all.
- **No monetisation:** no ads, fees, upsells, or broker links.
- **Privacy by design:** analysis runs in the browser. Nothing is uploaded or stored (only the language choice is saved locally). It never reads SMS, OTPs or financial records; it sees only what the user pastes, shares or uploads.
- **Transparent about uncertainty:** every result shows why, and explains what a score does and does not mean.

## Project structure
```
index.html, style.css      UI shell (text comes from locale files)
src/engine.js              pure, language-neutral analysis (runs in browser and Node)
src/rules.js               rule data: patterns, weights, official domains
src/locales/en.js, hi.js   all user-facing text, one file per language
src/app.js                 UI logic, voice, share target
dist/bharosa.js            single bundled script that index.html loads (generated by `npm run build`)
src/ocr.js                 on-device OCR (loaded only when needed)
sw.js, manifest.webmanifest  offline + installable + share target
tests/                     unit tests, labelled seed set, evaluation script
```

## Run, test, evaluate
```bash
npm start        # serves http://localhost:8080 (needs python3; or use any static server)
                 # or simply double-click index.html: it also works from disk
npm test         # 15 unit tests (node 20+)
npm run eval     # precision / recall on the labelled seed set
npm run build    # re-create dist/bharosa.js after you edit anything in src/ (run this before committing)
```

## Deploy
1. Create a public GitHub repository named `bharosa-check` and push this folder to `main`.
2. In **Settings > Pages**, set **Source** to **GitHub Actions**.
3. The included workflow runs tests, rebuilds the bundle, then publishes the live demo at `https://<your-username>.github.io/bharosa-check/`.

## Extend it
- **Add a rule:** add an object to `src/rules.js` and its text to each file in `src/locales/`. A test fails if text is missing in any language.
- **Add a language:** copy `src/locales/en.js`, translate, register it in `LG` in `src/app.js`.
- **Add a broker domain:** add one line to `BRANDS` in `src/rules.js`.
- After any change in `src/`, run `npm run build`. The page loads the single bundled script, so it works on any static server and straight from disk.

## Evaluation (read this honestly)
`tests/dataset.json` is a **synthetic seed set** of 19 messages (11 scam in English, Hindi and Hinglish; 8 genuine) written by the authors. On it the engine scores **100% precision, 91% recall, 0% false alarms** (threshold: score 20+). The one miss is a polite pitch with no known red-flag wording, which a rule engine cannot catch. This is a regression baseline, **not** a real-world accuracy claim. The first run exposed a false alarm on genuine advice ("check SEBI registration"), which we fixed in the rule. Contributing real, anonymised messages is the most valuable next step.

## Limitations and roadmap
- Checks text patterns, not facts: it does not query SEBI's live register (it links users to SEBI and SEBI Check instead).
- Domain check uses a small demo list of broker sites.
- OCR needs a one-time download of the OCR engine and language data, and has not been tested on a wide range of screenshots.
- Next: more regional languages, voice input, crowdsourced pattern feed, deepfake finfluencer checks, and distribution through SEBI, exchange and bank investor-awareness channels.

Educational investor-protection tool. Not investment advice. If money has been lost, call **1930** or visit **cybercrime.gov.in** right away.
